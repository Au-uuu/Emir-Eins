# QQ 官方机器人 —— 群聊助手骨架

基于官方 SDK [qq-botpy](https://github.com/tencent-connect/botpy) 的最小可运行机器人。
已验证：鉴权成功、WebSocket 网关连接成功、可接收群 @ / 群全量 / 单聊消息。

## 文件说明

| 文件 | 作用 |
|---|---|
| `bot.py` | 机器人主体：事件处理、指令、去重、限流 |
| `.env` | 凭据与配置（**不要外传、不要提交仓库**） |
| `.env.example` | 配置模板 |
| `smoke_test.py` | 启动前自检：导入、凭据、处理器、鉴权 |
| `start.ps1` | 一键启动 |
| `requirements.txt` | 依赖清单 |
| `privacy-policy.md` | 提交开放平台用的隐私协议 |

## 启动

```powershell
# 1. 自检（推荐每次都先跑）
.\.venv\Scripts\python.exe smoke_test.py

# 2. 启动
.\start.ps1
# 或
.\.venv\Scripts\python.exe bot.py
```

机器人必须**保持进程运行**才会回消息，关掉窗口就掉线。

## 配置项（.env）

| 变量 | 说明 |
|---|---|
| `QQ_BOT_APPID` | 开放平台「开发设置」里的 AppID |
| `QQ_BOT_SECRET` | 对应的 AppSecret |
| `QQ_BOT_KEYWORD` | 群「全量消息」模式的关键词；**留空 = 不开启全量响应（推荐）** |
| `QQ_BOT_COOLDOWN` | 同一群回复的最小间隔秒数，防刷屏 |

## 已实现的响应

| 场景 | 事件 | 行为 |
|---|---|---|
| 群里 @ 机器人 | `GROUP_AT_MESSAGE_CREATE` | 全部指令可用；**只有 @ 没有正文 → 视为 `/help`**；认不出的内容**直接无视**（不再回「收到：…」） |
| 群内全部消息 | `GROUP_MESSAGE_CREATE` | **需群主开启「接收所有消息」**；全部指令可用；非指令消息只在命中 `QQ_BOT_KEYWORD` 时响应 |
| 单聊 | `C2C_MESSAGE_CREATE` | 全部指令可用；空内容 → `/help`；认不出的内容直接无视 |

> 回复策略：机器人**只对有效指令/空 @ 做出回应**，其余消息一律静默忽略，避免在群里刷屏。

## 指令一览

> **对外指令**（建议在管理端「指令配置」里登记）：`/帮助`、`/添加`、`/批量添加`、`/来只`、`/删除`、
> `/图库`、`/关联`、`/取消关联`、`/查找关联`、`/私有`、`/公开`。
> 下面表里带 🛠 的是内部调试指令，仍然可用但不对外展示。

| 指令 | 说明 |
|---|---|
| `/help`（`/帮助`） | 查看帮助 |
| `/ping` 🛠（`/在线`） | 测试在线 |
| `/echo` 🛠（`/复读`） | 复读（上限 200 字） |
| `/添加 <关键词...>` | **引用一张图片消息**后回复本指令（斜杠可省）；或**同一条消息附带图片** + `/添加`（须带斜杠）。入库按 SHA-256 去重，没图片时保持安静 |
| `/批量添加 <关键词...>` | 一次把消息里（或引用消息里）的图片入库，**一次最多 5 张**；**须带斜杠** |
| `/来只 [关键词] [私有/公开/全部]` | 随机发一张图；层参数默认「全部」（公开+本群私有） |
| `/删除 <图库名> [私有/公开/全部]` | **引用一张图片**后回复，把这张图从该图库移除；默认「全部」＝私有优先、没有再公开 |
| `/图库` | 列出图库第 1 页（每页 25），按图片数降序，各图库用 ` / ` 隔开（不换行），如 `猫(12)-猫咪 / 狗[3]`；公开层用 `名称(数量)`，本群私有层用 `名称[数量]`；每个图库最多带 2 个关联词 |
| `/图库 <页码>` | 翻页，如 `/图库 2`；多页时末尾有提示，第 2 页起开头显示页码 |
| `/图库 <关键词> [页码]` | 回复该图库的**预览缩略图**（每页 8 张）并**完整展示关联词**；翻页 `/图库 猫 2`；**查不到时模糊推荐相关关键词** |
| `/图库 统计` | 查看统计（总数/占用/关键词数/今日新增/累计取用） |
| `/关联 <主关键词> <别名...>` | 建立关联：别名等价主关键词，如 `/关联 猫 猫咪 喵喵` |
| `/取消关联 <关键词...>` | 只把该关键词移出集合；移出主关键词会自动改选新主；删「集合仅剩的最后一个词」仅限管理员 |
| `/查找关联 [关键词]` | 查看某关键词的关联，或不带参数列出所有关联集合 |
| `/私有 <图库名>` | 群聊里：把图库设为**当前群私有**（群聊不接受第二个参数） |
| `/删除图库` | **仅管理员**：列出所有图库层（图库→群openid/公开） |
| `/删除图库 <图库名> <群openid\|公开>` | **仅管理员**：删除该图库的指定层 |
| `/添加名片 <备注>` | **引用一张图片**后回复，登记为自己的游戏名片；同一备注重复添加会失败 |
| `/游戏名片` | 把自己的名片**竖向拼成一张图**发送（宽 1920，每张上方一行 `【编号】.备注`） |
| `/删除名片 <备注\|编号>` | 删除自己的名片；或**引用图片**后 `/删除名片` 按指纹删 |
| `/查询标识` | 查询自己的 openid 与当前群 openid（不在普通帮助里，仅管理员私聊帮助可见） |

> **管理员私聊**里还可用 `/私有 <图库名> <群openid>`、`/公开 <图库名> <群openid>` 对指定群设置。
> `/help` 在管理员私聊里会返回**全部指令**；群里只显示用户指令。

斜杠规则：**只有** `添加`、`删除`、`来只` 可省略斜杠，如 `添加 猫`、`来只 deepseek`、`删除 猫`
（添加/删除需引用图片）。其余指令（`图库`、`关联`、`取消关联`、`查找关联`、`私有`、`公开`、`批量添加` 等）
**必须带 `/`**。

### 删除图片

- 用法：**引用一张图片**，回复 `/删除 <图库名称>`。
- 图库名可以不带斜杠，也可以是关联里的别名（会解析到主关键词）。
- 依次判断：图库是否存在 → 图库里有没有这张图的**指纹（SHA-256）**。
  - 图库不存在 / 图库里没有这张图 / 整个图片库都没有这张图 → 分别给出提示。
- 图片按指纹只存一份、可被多个图库共享，所以删除是**从指定图库移除**，
  其他图库不受影响；只有这张图不再被任何图库引用时，才清理磁盘文件。
- 删除或取消关联后，**没有任何图片的空关键词/空集合会被自动清理**。
  ⚠️ 因此关联最好在有图之后再建立，否则一次取消关联就会把空集合移除。

### 图库列表

- `/图库` 列出图库（每页 50 个），按图片数降序，形如 `猫(12)-猫咪-喵喵…`。
- 每个图库最多显示 2 个关联词，超出用 `…` 省略；完整关联词用 `/图库 <关键词>` 查看。
- 翻页：`/图库 2`。只有多于一页时，末尾才有 `…还有更多` 小提示；第 2 页起在开头显示页码。
- 统计信息改用 `/图库 统计`。

### 关键词关联（别名）

- 每个关联集合只有一个**主关键词**，所有别名**只连主关键词**，断连也只与主关键词断连。
- `/来只 B` 与 `/图库 B` 里的 `B` 若是别名，会先解析到主关键词，效果等价 `/来只 A`。
- `/添加 B` 也会把关键词解析到主关键词，库内只沉淀主关键词。
- 建立关联时会把**已用别名标注的存量图片合并到主关键词**。
- 关联结构是单层星型：若把某个集合的主关键词并进另一个集合，其别名会一并改挂到新的主，不会出现别名串联。
- **取消关联只移出单个词，集合不受影响**：移出别名只断它自己那一条边；移出主关键词时会从剩余成员里自动改选新主（取字典序最小者），其余成员保持关联，图片池也随集合迁到新主名下，旧主退化为普通关键词。

### 管理员与删除保护

- 关键词集合**仅剩最后一个词**时，普通用户不能删除（删掉它等于解散整个集合）。
- 管理员可以删掉这最后一个词：会把该关键词从所有图片上摘掉，不再被引用的图片连同文件清理。
- **管理员登记**：在**私聊**里发送 `管理员 <口令>`（口令见 `.env` 的 `QQ_BOT_ADMIN_PASSWORD`）。
  该指令只在私聊生效、不在 `/帮助` 中展示；群聊里命中会保持沉默，避免口令外泄。
- QQ 官方机器人拿不到 QQ 号，管理员只能按每人唯一的 **openid** 记录（登记时自动写入 `data/images.db`）。
- 撤销管理员：删除 `admins` 表里对应的 openid 即可。

### 群私有图库（分层模型）

图库身份 = `(关键词, owner_group)`：`owner_group=''` 是**公开层**（所有群/单聊可见），
否则是该群的**私有层**（只在该群可见）。同一关键词可以同时在多个群各自私有。

- `/私有 <图库名>`（群聊）：把该图库的**公开层图片全部移入本群私有层**；
  之后本群的 `/添加 <图库名>` 进私有层。其他群仍可往公开层 `/添加` 同名图库。
  群聊**不接受第二个参数**。
- `/私有 <图库名> <群openid>`：**私聊里仅管理员**可用，对指定群执行同样操作。
  群 openid 在群里发 `/查询标识` 获取。
- `/公开 <图库名>`（群聊）把本群私有层**并回公开层**；`/公开 <图库名> <群openid>`
  （私聊，仅管理员）对指定群取消私有。
- `/来只 <图库名> [私有/公开/全部]`：默认全部＝公开层 + 本群私有层。
- `/删除 <图库名> [私有/公开/全部]`：默认全部＝私有优先、没有再公开。
- `/图库`：公开层用 `名称(数量)`，本群私有层用 `名称[数量]`；同名两层会各占一条。
- 私有层在**别的群完全不可见**。
- **图库名不能是纯数字**（避免与 `/图库 页码` 冲突），也不能含空格。
- 图库名可以是关联里的别名（解析到主关键词后再分层）。
- `/图库` 列表里，本群的私有图库带 `[私有]` 标记。
- 一个图库最多绑定一个群；群标识用 `group_openid`（与 QQ 群号无关）。

### 游戏名片

- 名片属于**用户自己**（按 openid），与图库无关，不会出现在 `/来只` / `/图库` 里。
- `/添加名片 <备注>`：**引用一张图片**后回复，登记为一张名片；原图保存（按 SHA-256
  去重）；**同一备注重复添加会失败**并提示。
- `/游戏名片`：把该用户所有名片**竖向拼成一张图**发送——每张按宽 1920 等比缩放、
  宽度顶满，图片上方留一行 `【编号】.备注`；图过高时截断并提示。
- `/删除名片 <备注>` 或 `/删除名片 <编号>`：删自己的名片；或**引用图片**后
  `/删除名片` 按图片指纹删。
- 删除后会清理不再被任何图库/名片引用的原图与缩略图。
- ⚠️ 名片按机器人视角的 openid 归属；QQ 官方机器人拿不到 QQ 号，跨群/单聊的
  openid 是否一致取决于平台，可能需要分别添加。

**消息预处理**：匹配指令前会先剥掉正文开头的提及，**两种写法都认**：QQ 原始格式
`<@openid>`（引用/回复别人、全量模式下 @机器人 时开头会出现）和客户端显示的
`@昵称`。所以「引用图片 + 回复」开头的自动 @ 不会影响 `/添加`、`/删除` 等指令。
关键词解析时也会丢弃提及，避免把提及存成关键词。

### 图片库怎么工作

- **添加方式**：QQ 无法把图片和文字放在同一条消息里，所以用法是**引用一张图片消息**，
  再回复 `/添加 关键词`。平台会把被引用图片放在 `msg_elements` 里，
  但 botpy 不解析该字段，因此 `raw_events.py` 猴补丁了事件解析层以保留原始 payload。
- **存储**：图片按内容 SHA-256 命名，存在 `data/images/<哈希前2位>/`，元数据在 `data/images.db`（SQLite）
- **去重**：同一张图无论谁发、叫什么文件名，只存一份；再次提交只会补充新关键词
- **GIF 动图**：官方文档自相矛盾（概述正文说支持 gif/webp/bmp，文件类型表却只写 png/jpg）。
  现在的策略是 **GIF 原样保存、原样发送**：平台接受就保留动图；若被拒（`850019`），
  发送层会自动用 Pillow 转成 PNG 首帧重试，所以无论平台认不认都不会退化。WebP/BMP
  仍在入库时直接转 PNG
- **关键词**：空格/逗号/顿号分隔，统一转小写，单图最多 10 个、单个最长 24 字
- **发图**：本地图必须走「预上传 → 分片 PUT → 分片确认 → 合并」换 `file_info`，
  再用 `msg_type=7` 发送（`uploader.py` 自行实现，因为 SDK 只支持 URL 直传）。
  ⚠️ 平台返回的分片序号**从 1 开始**（不是 0），按 0 取偏移会切出空分片并报 850019
- **被动回复**：上传时 `srv_send_msg=False`，配合 `msg_id` 发送，**不占用主动消息频次**

### 新增配置

| 变量 | 说明 |
|---|---|
| `QQ_BOT_IMAGE_COOLDOWN` | `/来只` 的每群限流秒数，默认 3 |
| `QQ_BOT_IDLE_TIMEOUT` | 看门狗阈值：多久没收到网关消息就重启，默认 900 秒 |
| `QQ_BOT_ADMIN_PASSWORD` | 管理员口令：私聊发送 `管理员 <口令>` 自助登记为管理员；留空关闭。**敏感，勿外传** |

> ⚠️ **群主一旦开启「接收所有消息」（全量模式），@ 机器人也走 `GROUP_MESSAGE_CREATE`**，
> 平台不再单独推 `GROUP_AT_MESSAGE_CREATE`。而 botpy 1.2.1 没有这个事件的解析器，
> 必须在 `raw_events.install()` 里补一个（已实现），否则表现为「单聊正常、群里完全不理人」。
>
> 全量模式下指令对**所有群成员**生效，因此 `/添加`、`/来只` 加了群级限流（`QQ_BOT_COOLDOWN`）；
> 普通聊天不会被回复。若群主关闭全量模式，则只有 @ 才会触发。

## 长连接看门狗（重要）

botpy 的 WebSocket **可能静默失效**：进程活着、心跳循环还在跑，但事件再也收不到，
日志里也没有任何报错——表现为"机器人看着在线，其实完全不回复"。

`watchdog.py` 猴补丁了网关消息入口，记录最后一次收到下行消息的时间；
超过 `QQ_BOT_IDLE_TIMEOUT` 没有活动，就以 **exit code 2** 退出进程。

配合 `run_forever.ps1` 使用可自动重启：

```powershell
.\run_forever.ps1     # 检测到 exit 2 会等 5 秒后自动拉起
```

安静的小群请把 `QQ_BOT_IDLE_TIMEOUT` 调大（如 3600），否则长时间没人说话会被误判。

### 发现机器人"不理人"时的排查顺序

1. 看 `logs/bot.log` 有没有**收到消息事件**的记录（如 `[群@]`）
   - **没有** → 消息没送达机器人：确认在群里 **@ 了机器人**，且连接没静默失效
   - **有** → 事件到了但处理出错，看后面的 `[ERROR]` 和 `Traceback`
2. 确认只有一个机器人实例在跑（多实例抢连接会导致事件只投递给其中一个）
3. 确认不是**主动消息权限**问题：未认证的机器人不能主动推送，
   所有回复都必须由用户消息触发（被动回复）

## 关键限制（官方规则）

- **被动回复窗口**：群聊 5 分钟内、每条消息最多回 5 次（单聊 60 分钟 / 4 次）
- **主动消息频控**：认证后 60 条/分钟，**每个群每天 1000 条**上限
- **消息去重**：相同 `msg_id` 可能重复推送，代码已做 5 分钟去重
- **全量模式慎用**：50 人群里对所有消息都回复会撞频控，务必靠关键词 + 限流过滤

## 安全提醒

AppSecret 等同于机器人密码。若曾以任何形式泄露（截图、聊天记录、公开仓库），
请前往开放平台「开发设置」重置，然后只更新 `.env` 里的 `QQ_BOT_SECRET`，代码无需改动。
