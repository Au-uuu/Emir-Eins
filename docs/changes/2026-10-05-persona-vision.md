# 人格聊天看图：带图消息整体切换到视觉模型

日期：2026-10-05

## 需求

人格聊天上线后，用户发现机器人「看不见」图片：发图它没反应，追问「这张图好可爱」
它也只能装傻。排查确认两道原因叠加：

1. `qwen-flash-character` 是**纯文本**模型（Text in / Text out），没有图片输入接口；
2. 代码在进模型前就把图片丢掉了——入口只取文字，单聊只发图只记一条
   「（发了一张图片）」占位。

用户指定方案 **B：带图消息整体切换到视觉模型**，同时要求保留人设。

## 设计

### 人设怎么保留

人设不在模型里，而是靠角色卡 `persona/依蜜尔爱因.md` 整份作为 system prompt。
视觉链路**用同一张卡、同一段历史、同样的温度/长度限制/三道静默**，只换模型名。
带图请求的 user content 换成 OpenAI 多模态数组：图片在前（base64 data URI）、
文字在后。

### 链路

| 环节 | 处理 |
|---|---|
| 模型 | `QQ_BOT_QWEN_VL_MODEL`，默认 `qwen3-vl-flash`（同 Key、同 DashScope 兼容端点）；设 `off` 整体关闭 |
| 取图 | 复用图库的 `collect_image_attachments`（含引用消息里的图）+ `store.download`；归一化复用 `ImageStore._normalize`；GIF 只取首帧转 PNG |
| 限额 | 一次最多 3 张、单张 ≤8MB，超限/失败只跳过那一张，绝不抛异常 |
| 触发 | 单聊非指令带图、单聊只发图、群@ 带图（含只 @+图无正文）；群全量被 @ 同理 |
| 回退 | 图全部不可用 / 未开看图 / 下载失败 → 旧行为：不回复，上下文记「（发了一张图片）」占位 |
| 记忆 | 上下文数据库仍只存文本（占位 + 模型回复），图片**不落盘、不入库** |

### 行为变化（对照旧契约）

| 场景 | 旧行为 | 新行为 |
|---|---|---|
| 单聊只发一张图片 | 静默，记占位 | **看图后用角色口吻回复**，占位照记 |
| 群里 @ 机器人且带图、无正文 | 视为空 @ → /help | **看图回复**；图不可用时仍回退 /help |
| 单聊/群@ 文字 + 图片 | 图片被无视，纯文本回复 | 模型看着图回复 |

2026-09-28「单聊发图静默」的契约**保留了一半**：回复与否现在取决于能不能看到图，
但「占位照记、下一句接得上」的约定不变；且人格聊天未配置时依然只记占位不回复。

## 踩过的坑

1. **把「只发图记占位」挪进 `persona_reply` 后被 `available()` 提前 return 拦掉**：
   旧代码在单聊 handler 里无条件记占位（人格聊天没配置也记），挪进来后先撞上
   `if not persona.available(): return`，`_test_reply_policy` 的两项「会记入上下文」
   直接红掉。修正：占位兜底放在 `available()` 判定**之前**（敏感词过滤仍最先，
   命中即整个静默不记）。
2. 多行 `python -c` 在本机 shell 里会静默不执行（无输出、无报错）——排障时先写成
   临时脚本再跑，别怀疑代码。

## 已知限制

- 上下文里只存「（发了一张图片）」占位 + 模型回复的文本；若模型回复没提到图的内容，
  后续纯文本轮次对图的认知有限（实测角色模型看图后通常会主动描述，暂不加描述调用）。
- 视觉模型不是角色特调，语气贴合度弱于 `qwen-flash-character`，待人工观察（见上）。
- QQ 侧表情包若不带图片附件（商城大表情），本来就取不到图，维持原静默逻辑。
