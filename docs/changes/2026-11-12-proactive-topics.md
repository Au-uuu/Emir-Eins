# 随机接话：先总结当前群话题 + high 思考

- 日期：2026-11-12
- 模块：`group_context.py`、`bot.py`
- 配置：`QQ_BOT_GROUP_TOPICS`（默认 `1`）、`QQ_BOT_PROACTIVE_WINDOW_MINUTES`（默认 `10`）

## 现象

群里有多个话题或刚切换话题时，随机接话容易接旧话题、答非所问。  
原因不是没有上下文，而是：

- 最近 30 条 / 30 分钟一起塞进去，话题一多就稀释；
- 没有“当前话题”锚点；
- 随机接话 `reasoning=0`，纯一遍生成。

## 改动

### 随机接话（`proactive=True`）

1. 先调**主模型**（不是便宜模型）把最近 10 分钟群聊压成 1~3 个当前话题：
   - 只列还在聊的，按最近消息排序，每条 ≤20 字；
   - 缓存 60 秒，避免同一话题重复总结；
   - 失败返回空，回退到原始群聊上下文。
2. 上下文只取最近 **10 分钟 / 最多 15 条**，减少旧话题和已结束话题干扰。
3. 注入 `【当前群话题（最近 N 分钟，按最近消息）】...`，提示词要求：
   - 只接当前话题；
   - 多个话题时选最近 3 条消息里的；
   - 只接最近 10 分钟，超过窗口的旧话题不接。
4. 回复用 `reasoning_effort=high`。
   - `high` 实测可能 30~60 秒，因此线上 `QQ_BOT_CHAT_TIMEOUT` 从 30 放宽到 **90 秒**；
   - 只在随机接话使用，被 @ 的普通闲聊不占用这个延迟。

### 被 @（`proactive=False`）

- 保持完整群聊上下文；
- 普通闲聊 `reasoning=None`，不额外增加延迟；
- 命中数值/资料/知识库/联网的事实题仍保留 `low`，避免回到“凭印象报数值”。

## 成本

- 随机接话本身有概率 + 300 秒冷却，不是每条都触发；
- 每次多一次主模型话题总结（约 1k 输入 / 几十输出）+ 一次 `high` 思考；
- 用户明确表示额度用不完，因此不用便宜模型，直接主模型。

## 配置

```ini
QQ_BOT_GROUP_TOPICS=1              # 0 = 关闭话题总结
QQ_BOT_PROACTIVE_WINDOW_MINUTES=10 # 只看最近多少分钟
QQ_BOT_CHAT_TIMEOUT=90             # high 需要留足超时
```

## 测试

`_test_group_context.py` 新增：

- 话题摘要 JSON 解析；
- 60 秒缓存命中（第二次不再调模型）；
- 随机接话注入 `【当前群话题】`；
- 随机接话 `reasoning=high`；
- 被 @ 闲聊 `reasoning=None`；
- `render(since_ts=...)` 排除过旧消息。
