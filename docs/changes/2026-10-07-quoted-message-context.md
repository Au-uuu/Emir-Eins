# 引用消息接入：引用文本喂给模型 + 转发卡片里的图也能看

日期：2026-10-07

## 需求（实锤过程）

用户引用一张「群聊的聊天记录」（合并转发卡片）@ 机器人问「这句话啥意思」，
机器人回复了一段**凭空捏造**的「白兔表情包」分析——没图没上下文，纯脑编。

抓包（`QQ_BOT_DUMP_EVENTS=1`）看清了平台行为：

| 场景 | message_type | 数据形态 |
|---|---|---|
| 合并转发卡片直接发出 | 102 | `content` **就是平台展开的文本摘要**：`[群聊的聊天记录]` + `=== 消息 N ===`（每条的发送者、文字内容、图片附件的下载 URL+rkey） |
| 引用某消息 + @ 机器人提问 | 103 | 被引用内容的展开文本在 `msg_elements[].content`，带 `[消息类型] 引用消息` 标记；引用的**图片不在 attachments 里**，而是以 `URL:https://…` 形式内嵌在文本中 |

也就是说：**数据一直都在**（平台连转发卡片都展开了），但代码只收集了引用的
图片、引用的文字从未喂给模型——模型拿到光秃秃的「这句话啥意思」，只能照着
历史里回图的风格脑编。

## 设计

- **`quoted_content(message)`**：抽取带 `引用消息` 标记的元素文本（≤600 字），
  其中 `URL:…` 对模型无用，抹掉省 token。
- **`collect_vision_images()`**：引用文本里内嵌的图片 URL 也进取图候选
  （与 attachments 去重，共享 3 张上限与体积/格式规则）——引用转发卡片时
  卡片里的图能被真正「看到」。
- **`persona_reply()`**：有引用时模型输入 = `（用户引用了下面这条消息提问：…）`
  + 用户正文；**只拼当前轮，历史里仍存原文**，记忆不膨胀。敏感词过滤、限流、
  三道静默全部不变（过滤只扫用户正文与回复，不扫引用块）。

## 改动文件

| 文件 | 说明 |
|---|---|
| `bot.py` | 新增 `quoted_content()`；`collect_vision_images()` 重构为「候选 URL 收集 → 统一下载」；`persona_reply` 拼引用文本 |
| `_test_persona.py` | 新增 [6] 引用消息 5 项断言 |
| 服务器 `.env` | 诊断期 `QQ_BOT_DUMP_EVENTS=1`（**稳定后记得关回 0**） |

## 已知限制

- 卡片摘要里文字消息的内容平台会给，但**被折叠的长记录**（几十条）超出 600 字
  截断——截断处会打在半句话上，属可接受损耗。
- 引用块不进历史：下一轮再问「刚才引用的那条」时，模型只能靠上一轮自己的回复
  回忆，和图片的占位机制同理。
