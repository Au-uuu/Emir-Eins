# 看图升级：单发 GIF 抽首/中/尾 3 帧

日期：2026-10-07

## 需求

看图上线后确认：GIF 一律只取第一帧，「梗在后面」的动图模型看不懂。用户选定
**三帧采样**方案（对比过视频理解：token 是单帧的 4~10 倍，还要在服务器装 ffmpeg
转封装，不值）。

## 设计

- `image_store.py` 新增 `sample_frames_png(data, count)`：PIL 均匀抽 count 帧
  （首/中/尾，去重应对短动图），每帧转 PNG；静止图/任何失败返回 `[]`。
- `bot.py` `collect_vision_images()` 规则：
  - **单发一张 GIF** → 抽 `VISION_GIF_FRAMES=3` 帧当 3 张图发给模型，
    正好用满单次 3 张的名额；抽帧失败退回首帧。
  - **多图混发**（含 GIF）→ 每张只占一个名额，GIF 仍只看第一帧——名额留给
    「每张图都有份」，不给一张动图吃光。
  - 超大帧（>8MB）过滤，全被滤掉则退回首帧。
- 不改 `first_frame_png()` 的任何行为（发送链路还在用它）。

## 已知限制

- 动图 webp（少见）仍只看第一帧：`_normalize` 会把 webp 转成 PNG 首帧，
  抽帧只对 GIF 生效。
- 3 帧是从「帧序列均匀取样」，不是场景切分——一段 10 秒只有两三个动作的 GIF
  可能抽到近似重复帧（去重只按帧序号，不按画面内容）。
