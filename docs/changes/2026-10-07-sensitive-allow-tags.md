# 敏感词误杀角色标签：【抗议】【游行】【示威】放行

日期：2026-10-07

## 需求（实锤过程）

用户群里发图 @ 机器人问「这是什么」，机器人**完全沉默**。查日志：

```
18:06:44 [群全量] group=… 这是什么 [+@本机]
18:06:50 [WARNING] [人格] 模型回复命中敏感词「抗议」，已丢弃
```

机器人看到了、也看图生成了回复，但回复里带【抗议】标签（角色卡的标签系统），
被敏感词过滤器当成键政词整段丢弃——用户视角就是「装死」。

词表（konsheng/Sensitive-lexicon 政治类）里还有同类的 **游行、示威**：看图描述
（图里真有游行队伍时）与对话都会被误杀。这是角色卡标签系统/看图功能与敏感词
表的系统性冲突，不是单点 bug。

## 设计

- **`deploy/sensitive_allow.txt`** 加 `抗议 / 游行 / 示威` 三个词（构建词表时剔除，
  与「政府」同等的日常词处理）。改词表只走放行名单，不手工维护词表文件。
- **`bot.py`** 回复被敏感词丢弃时的日志带上回复开头 60 字——这次排查最大的摩擦
  就是「日志只有一个词，完全不知道模型说了什么」。

## 改动文件

| 文件 | 说明 |
|---|---|
| `deploy/sensitive_allow.txt` | +抗议/游行/示威 |
| `bot.py` | 丢弃日志附回复片段 |
| 服务器 `data/sensitive_words.txt` | 立即 `sed` 剔除 3 词（不等下次跑 fetch 脚本） |

## 测试报告

### 自动化（本机，2026-10-07）

- 全套件 **16/16 通过**（含 `_test_persona` 敏感词段——断言查的是「被丢弃不发送」
  行为，不锚定日志文案）

### 服务器验证

- 词表剔除后 grep 命中 0；`WordFilter.hit("【抗议】…")`、`hit("图里是游行队伍")`
  均返回 None ✅（过滤仍然生效，只是这三个词放行）
- 部署重启后启动日志正常

## 备注

- 三道静默的设计不变：宁可装死也不能把键政词发出去。放行 ≠ 关闭过滤，
  词表仍有 1198 条在岗。
- 若将来模型新增常用标签/句式被误杀，同样走 `sensitive_allow.txt` + 重跑
  `deploy/fetch_sensitive_words.sh`。
