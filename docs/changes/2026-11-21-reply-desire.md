# 随机接话改为「回复欲望」：先积累上下文，再决定接不接

- 日期：2026-11-21
- 模块：`random_reply.py`、`bot.py`、`group_context.py`

## 现象

11-18 13:29，管理群收到一条 `[群聊的聊天记录]`，随机接话 3% 命中，bot 立刻回复：

> 六个人齐声问同一个压缩包怎么解压……本机赌里面没有压，只有复读。

问题是：

- 这是一条转发的旧聊天记录，不是当前正在聊的话题；
- 纯按单条消息 3% 掷骰子，没有“这个话题已经聊起来了”的判断；
- 回复时可能已经过了那个话题的时效。

## 改动

### 1. 回复欲望

`random_reply.py` 增加按群的欲望计数：

- 每来一条**可接**的普通消息，欲望 +1；
- 两次消息间隔超过 `QQ_BOT_RANDOM_REPLY_WINDOW`（默认 180 秒）就重新累计；
- 至少积累 `QQ_BOT_RANDOM_REPLY_MIN_MESSAGES`（默认 3）条，才进入掷骰子阶段；
- 欲望越高，实际回复概率略升，但不超过 50%；
- 接完一次后欲望清零。

这样不会再看到一条孤立消息/一条转发记录就接。

### 2. 旧内容和无效内容不增加欲望

- 聊天记录 / 合并转发（`message_type=102` 或正文含“聊天记录”）直接跳过，并清空该群欲望；
- 引用别人的消息、低信息短句（“好”“？”“草”）、斜杠指令、卡片、空消息都不接；
- 这些内容 @ 机器人时仍正常处理，只是不参与随机接话。

### 3. 时效窗口缩到 5 分钟

随机接话的话题总结和上下文从 10 分钟缩到 **5 分钟**，
`QQ_BOT_PROACTIVE_WINDOW_MINUTES` 默认改为 `5`。

### 4. 顺手修 Cooldown

`Cooldown.allow()` 原来用 `0.0` 当“没有记录”，进程刚启动的前 N 秒会把所有新 key 误判为冷却中；
改为 `None` 判断。无冷却时不再误杀。

## 配置

```ini
QQ_BOT_RANDOM_REPLY=0.03
QQ_BOT_RANDOM_REPLY_COOLDOWN=300
QQ_BOT_RANDOM_REPLY_MIN_MESSAGES=3
QQ_BOT_RANDOM_REPLY_WINDOW=180
QQ_BOT_PROACTIVE_WINDOW_MINUTES=5
```

## 测试

`_test_random_reply.py`：

- 第 1、2 条不接，第 3 条才接；
- 接完欲望清零；
- 聊天记录不接；
- 原有概率 0、冷却、引用、低信息过滤、处理器接线全部通过。
