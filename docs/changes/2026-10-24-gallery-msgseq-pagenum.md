# 2026-10-24 /图库 预览修复与翻页编号：msg_seq 计数、页码、跨页连续编号

## 需求

1. 用户反馈「连着发两条消息有一条没回」。排查（详见当日群反馈记录的姊妹篇）
   发现两个原因，其一为本记录所修：**`/图库 <关键词>` 的第二条回复（文字清单）
   从未送达过**——预览拼图与文字头是对同一条消息的两条回复，都发默认
   `msg_seq=1`，第二条被 QQ 判成重复整条拒掉（40054005）。10-14/10-20/10-22
   的 4 次预览全部中招，无一幸免。
2. 预览图下方要显示**页码 1/n**（原本写在文字头里，但文字头被 1 吞了，
   等于从没显示过）。
3. 翻页后拼图左上角的编号不要从 1 重来，要**接着上一页的最大值递增**。

## 设计

| 改动 | 说明 |
|---|---|
| `bot.py` 新增 `next_msg_seq(msg_id)` | 按 msg_id 维护自增计数（dict，超 1024 丢旧一半；msg_id 五分钟即失效）。同一条消息要回多条时每次取号 |
| `_reply_image_bytes` | 图片回复带 `msg_seq=next_msg_seq(...)`；重试循环里也取新号（上一次失败可能已占号） |
| `do_gallery` 文字头 | `msg_seq=next_msg_seq(message.id)`——拼图占 seq 1、文字拿 seq 2；拼图失败降级时文字自然拿 seq 1 |
| `do_gallery` 页码 | 文字头首行改为 `关键词「x」共 N 张 · 页码 {page}/{pages}（每页 8）` |
| `make_contact_sheet` 加 `start` | 左上角序号从 start 连续编号，跨页不归零；黑底标签宽度随位数自适应（三位数不挤出） |
| `_text_image_list` 加 `start` | 清单行改为 `{连续编号}. #{id} WxH 关键词`，与拼图角标一一对应（之前角标 1..8、清单却是 #id，声称对应其实对不上） |
| `_r6_fetch` 注释 | 「必须自己维护 msg_seq 计数器」改为指向现成的 `next_msg_seq` |
