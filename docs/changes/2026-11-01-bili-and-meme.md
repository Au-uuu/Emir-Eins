# B 站链接抽帧 + 独立梗库

- 日期：2026-11-01
- 模块：`bili.py`、`meme.py`、`learning.py`、`bot.py`、`video_frames.py`
- 数据：`data/meme.db`

## 一、B 站视频解析

### 背景

- 原代码只处理 **QQ 消息自带的视频附件**；B 站链接只是普通文字，没有被解析。
- 直接用 `yt-dlp` / 抓网页会失败：B 站对机房 IP 返回 **HTTP 412 Precondition Failed**。
- 实测本机：首页 200、`view`/`playurl` 接口带浏览器头 + `buvid3` 后 200、视频网页 412。
  这是 B 站风控，不是腾讯云防火墙；阿里云机房同样可能被拦。隔壁能用可能是登录 Cookie、代理或第三方解析。

### 实现

`bili.py` 走 B 站官方 JSON 接口，不依赖第三方解析站：

1. 识别 `bilibili.com/video/BV...`、`av...`、`b23.tv` 短链；
2. 自动取匿名 `buvid3` Cookie + 浏览器请求头，遇到 `-412/-352` 刷新 Cookie 重试一次；
3. `x/web-interface/view` 取标题/UP/时长/简介；
4. `x/player/playurl` 取 DASH 视频流（优先 avc、低清 360p/480p，不要音频）；
5. 下载上限默认 40MB（超出只取前段），ffmpeg 抽帧；
6. 元数据 + 帧交给视觉模型。

### 触发

- 群里发 B 站链接并 @ 机器人，或引用带 B 站链接的消息提问；
- 主动接话（`proactive=True`）只取标题，不下载视频，避免随机烧流量。

### 抽帧参数

默认每 **10 秒**一帧，最少 9 帧、最多 24 帧；长视频达到帧数上限时会自动放宽间隔。  
「每 10 帧」按 30fps 约等于每秒 3 张，长视频不现实，所以按时间采样。

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_BOT_BILI` | `1` | `0` 关闭 |
| `QQ_BOT_BILI_MAX_MB` | `40` | 视频流下载上限 |
| `QQ_BOT_BILI_INTERVAL` | `10` | 每多少秒一帧 |
| `QQ_BOT_BILI_MIN_FRAMES` | `9` | 最少帧数 |
| `QQ_BOT_BILI_MAX_FRAMES` | `24` | 最多帧数 |
| `QQ_BOT_BILI_MAX_DESC` | `300` | 简介最多带多少字 |

实测 `BV1GJ411x7h7`（3:33）：解析 + 下载 + 抽帧 **3.6 秒**，22 帧，视觉描述约 **22 秒**。

### 限制

- 1080p 需要登录 Cookie，抽帧用 360p/480p 足够；
- 付费、地区限制、需要登录的视频可能取不到流，会退回只给标题/简介；
- B 站接口以后可能改，已做 `buvid3` 刷新重试，但不能保证永远不 412；
- 22 帧的描述比普通看图慢。

## 二、独立梗库 `meme.py`

### 为什么要独立

- `memory_store.slang` 是**本群黑话**，按群隔离，主要从群聊上下文推断；
- 梗库是**全局**的，跨群共享，来源可以是联网检索、对话里别人解释、管理员手写；
- 单独 `data/meme.db`，不污染群记忆，也不会因为删某个群的黑话把通用梗删掉。

### 三条学习路径

1. **主动查**：`/梗 查 词`（任何人可用）。本地没有就联网查，查完入库；查不到会明说，不编。
2. **对话里学**：聊天里出现「X 是什么梗 / 什么意思」时，现有联网搜索拿到摘要，后台再整理成结构化词条存下来，不阻塞当前回复。
3. **后台补**：每轮自动学习时，从本群自动黑话里挑 **3 字及以上、置信度 ≥0.75** 的词，最多尝试 2 个/轮，联网核实入库。

### 质量控制

- 置信度低于 `QQ_BOT_MEME_CONF`（默认 0.55）不入库；
- 命中敏感词的词条直接丢弃；
- 手写/已核验条目不会被自动结果覆盖；
- 模型判断「不是梗 / 置信度不足」进 **30 天拒绝缓存**，不会每轮反复烧搜索额度；
- 每条记录来源（手写/联网/对话）、置信度、更新时间，可 `/梗 来源 词` 查。

### 指令

| 指令 | 说明 |
|---|---|
| `/梗` | 看最近收录 |
| `/梗 查 词` / `/梗 词` | 查梗，本地没有就联网 |
| `/梗 来源 词` | 看来源、置信度、更新时间 |
| `/梗 学 词` | 管理员：强制联网重查 |
| `/梗 添加 词 解释` | 管理员：手写，自动结果不覆盖 |
| `/梗 删 词` | 管理员：删除 |
| `/help 梗` | 完整用法 |

### 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_BOT_MEME` | `1` | 梗库开关 |
| `QQ_BOT_MEME_SEARCH` | `1` | 允许联网查梗 |
| `QQ_BOT_MEME_AUTO` | `1` | 后台自动补梗 |
| `QQ_BOT_MEME_CONF` | `0.55` | 入库置信度门槛 |
| `QQ_BOT_MEME_DB` | `data/meme.db` | 数据库路径 |

### 限制

- 搜索摘要是模型转述的，DashScope 搜索接口不返回原始 URL，所以只能记「来源=联网整理」，不能给可点链接；
- 不是真正的 tool calling，是「预搜索 + 后整理」，新梗有滞后；想立刻要就 `/梗 查`；
- 普通词仍可能误判，后台已用「≥3 字 + 高置信度 + 拒绝缓存」压住，但不能 100% 干净。

## 三、Webhook 现状（只调研，未改代码）

- 当前 `botpy 1.2.1` + `client.run()` 是 **纯 WebSocket**，不支持 Webhook。
- 平台支持 WebSocket / Webhook 切换；回调必须是 HTTPS，端口只允许 80/443/8080/8443，需要 Ed25519 验签和 `op=13` 验证。
- 要切需要：升级 `qq-botpy-v2[webhook]` 或自写 aiohttp 回调 + 验签；准备域名 + TLS；管理端切模式。
- 现阶段单机长连接 + 看门狗已稳定，暂不切；保留双模式方案。
