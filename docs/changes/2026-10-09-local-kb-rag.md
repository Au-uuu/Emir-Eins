# 本地知识库检索（文字 RAG，轻量 BM25）

日期：2026-10-09

## 需求

用户希望在服务器本地加 RAG，提高**文字回复的事实准确率**（图库太小，图像相似检索不做）。

## 设计

新增 `kb.py`：**纯本地 BM25 检索，零第三方依赖**。

- **语料**：`data/kb/*.md` / `*.txt`（以 `_`/`.` 开头的文件不参与检索，用于放说明）。
  按空行切段，过长段硬切；启动后**懒加载一次**（改文件需重启）。
- **中文分词**：不引入 jieba，中文按**字符二元组**切（「佩丽卡」→ 佩丽/丽卡），英文按单词切。
- **检索**：BM25（k1=1.5, b=0.75），返回分数 ≥ 阈值的前 N 段。
- **注入**：`bot.py::persona_reply` 在调用模型前，用**用户消息文本**检索，命中就拼一段
  `（本机知识库检索到以下资料…）` 到提示词最前；无命中零开销。
- **角色卡 §0**：新增一条——知识库资料只提供**事实**，语气/自称/标签仍按人设，
  不许照抄原文、不许说「知识库/检索」这类字眼。

配置（`.env`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_BOT_KB_DIR` | `data/kb` | 知识库目录；不存在/为空则整体跳过 |
| `QQ_BOT_KB_TOP` | 3 | 每次返回几段 |
| `QQ_BOT_KB_MIN_SCORE` | 1.5 | 相关度下限 |

## 为什么不向量检索

服务器 4 核 / 3.6G 内存，Camie 打标已常驻 ~1.5G。向量检索要再常驻一个 embedding 模型，
内存吃紧；BM25 纯 Python，几千段的索引和查询都是毫秒级，几乎不吃内存，够用。
（日后若语料很大、BM25 召回不够，再考虑加向量检索。）

## 备注

- 知识库内容由用户维护；只放**事实**，别放会改变人设的内容。
- 检索基于**用户消息原文**；纯图片消息（无正文）不触发。
