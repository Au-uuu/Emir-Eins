# 知识库纳入坚果云异地备份

日期：2026-10-11

## 需求

本地知识库 `data/kb/`（13 部作品 + 魔裁 + 蓝色大肥鱼，约 1900 条 / 1.1 MB）是服务器上的
**唯一副本**：`data/` 被 `.gitignore` 忽略（不进 git），而此前的坚果云备份只覆盖
`images/ thumbs/ images.db`。一旦服务器出事，KB 会丢——虽然能重建，但要数小时 + 烧额度。

## 改动

`deploy/backup-nutstore.sh` 新增一段：

```bash
if [ -d "$DATA_DIR/kb" ]; then
    rclone copy "$DATA_DIR/kb" "$REMOTE/kb" \
        --transfers 2 --checkers 4 --retries 5 --low-level-retries 10 -v $DRY || rc=$?
fi
```

沿用既有约定：`copy` 只增不减、并发克制、`flock` 防重入。远端目录 `nutstore:qqbot-backup/kb/`。

## 部署

备份脚本不在 `upload.ps1` 的自动清单里（历来手动部署）：
scp 到 `/tmp` → 覆盖 `/opt/qqbot/deploy/backup-nutstore.sh` →
`sed -i 's/\r$//'`（去 CR，Windows 编辑后必备）→ `chmod +x`。
旧脚本备份在 `/root/backup-nutstore.sh.bak-<日期>`。

## 测试

- 手动跑一次：`Transferred: 16 / 16, 1.141 MiB`，退出码 0，日志 `备份完成`。
- 哈希回验：随机抽 3 个文件从云端下回来比对 SHA-256，**3/3 一致**
  （只对单文件下载比对，不递归列目录，避免打爆坚果云免费版请求限额）。

## 备注

- 定时任务不变（root crontab `30 3 * * *`），此后每天自动。
- KB 重建会整文件改写，rclone 的「大小+修改时间」比对会重传变更文件（量小，无碍）。
- 仍未纳入备份：`chat.db` / `push.db`（会话记忆、公告去重状态）；如需要可再加。
