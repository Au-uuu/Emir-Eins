# WD14 本地打标接入：动漫角色识别的「识别线索」

日期：2026-10-07

## 需求

用户拍板：群友的图库标注不当识别依据（已撤销）；识别知识用**开源可靠数据**。
选定 **WD14 Tagger**（SmilingWolf/wd-swinv2-tagger-v3，Danbooru 数百万图训练的
开源 ONNX 模型）——它本身就是内置的「特征→角色名」速查表（character/copyright
标签 + 置信度），本地 CPU 推理，零 API 费用。

## 服务器实测（部署前，本机 4C/3.6G）

| 图 | character 标签（BGR） | 置信度 |
|---|---|---|
| 初音未来 V6 官方立绘 | `hatsune_miku` | **0.99** |
| 明日方舟周边货架 | `w_(arknights)` | **0.94** |
| 群内像素梗图（群标「菲比」） | `ninomae_ina'nis`（hololive 一之濑千鹤） | 0.36 |
| **终末地三人立绘** | **空**（最高 0.00） | — |

- **通道顺序铁证**：同一张周边图，BGR 下 `w:0.94`，RGB 下全是垃圾（among us 0.01）
  ——官方示例的 `RGB→BGR` 翻转必须保留。
- **终末地空白**符合预期：v3 训练数据停在 2023-24，2026 年新角色不在标签表——
  这类角色继续靠卡片速查表兜底，WD14 覆盖其余几千个已收录角色。
- 群标「菲比」实际是千鹤梗图——侧面印证「群友标注不可靠」，撤得对。
- 推理耗时：稳定 ~2 秒/张（首张含预热 ~4 秒），线程池里跑，不堵事件循环。

## 设计

- **`tagger.py`**（新模块）：懒加载 ONNX 会话（进程内一次），`tag_image(bytes)` →
  (character 标签, copyright 标签)。阈值 0.35（实测正确匹配最低 0.36、错误 ≤0.13）。
  模型文件在 `models/wd-swinv2-tagger-v3/`（不进 git、不进 data/ 备份），缺失或
  加载失败 → 打标静默禁用，看图链路零影响。
- **`bot.py`**：`tagger_hints()` 只打标第一张图；命中时在模型输入最前拼
  `（识别线索：本机离线打标器认为图中含 角色=hatsune_miku；作品=vocaloid…）`，
  中文译名由 qwen 翻译；未命中零开销。
- **角色卡 §8**：新增「善用识别线索」条目（翻译采用、矛盾以画面为准求证）。
- **requirements.txt**：+onnxruntime。

## 已知限制

- WD14 只认 Danbooru 已收录角色；终末地等 2025+ 新游戏角色需等社区更新模型
  或走卡片速查表。误标可能（0.35 阈值下低概率），卡片已要求与画面矛盾时以画面为准。
- 只打标第一张图（多图消息的后续图不打标，省 CPU）。
