# 动漫识别修复：删除误导性速查表 + 角色候选线索

日期：2026-10-09

## 现象

用户反馈私聊发图识别不准：**最后一张「陈千语」（终末地）被认成「佩丽卡」，前面几张也不对**。

## 排查（看日志）

私聊逐张打标结果（Camie）：

| 时间 | 打标结果 |
|---|---|
| 15:11 | `作品=arknights`（**无角色**） |
| 15:12 | `作品=azur_lane,kantai_collection`（无角色） |
| 15:13 | `作品=honkai:_star_rail,honkai_(series),arknights`（无角色） |
| 15:13 | `无标签命中` |

两个原因：

1. **角色卡里有一张手写速查表**（10-07 尚无离线打标器时加的）：
   `黑长发 + 赤色角 + 机械臂/义体 → 佩丽卡`。陈千语同样「有角 + 义体元素」，在**没有角色线索**时
   模型就按这张表硬套成了佩丽卡。
2. **打标硬阈值太高**：角色阈值 0.5，而实测正确角色常落在 0.4~0.5（库里图片 top 角色分数：
   0.35 / 0.41 / 0.45 / 0.52 / 0.60 …），于是**多数图一个角色都不给**，模型只能瞎猜。

## 改动

1. **删除角色卡 §8 的「常见角色速查」**，改为明确禁令：
   「不许凭特征硬套角色名（有角+机械 ≠ 佩丽卡）；只认识别线索或可明确断定的经典角色，
   否则只描述特征 +【疑问】求证，宁可不报也不认错。」
   并补充：给的是「角色候选（低置信）」时只作参考、须与画面核对。
2. **新增「角色候选」软线索**（`tagger.py` + `bot.py`）：
   - `tagger.py`：新增 `_candidates()`（置信度 ≥0.25 的前 3 个角色，**不管是否过 0.5 阈值**）、
     `tag_image_detail()` 返回 `(角色, 作品, 候选)`；`tag_image()` 保持旧签名不变（兼容）。
   - `bot.py::tagger_hints()`：没有过硬阈值的角色时，把候选拼成
     `（角色候选（低置信，仅供参考、务必与画面核对）：xxx(0.45)、yyy(0.30)）`
     一起喂给视觉模型；日志也打 `[打标] …；角色候选=…`。

  `（角色候选（低置信…）：ouro_kronii(0.35)、meltryllis_(fate)(0.27)…）`。

## 备注

- `作品` 标签仍有噪声（一张图可能给 `original,pokemon,kantai_collection,twitter` 多条），
  角色卡已声明「dabooru 标签与画面矛盾时以画面为准」；若仍误导，下一步可对作品做 top-2 + 提高阈值。
- 候选线索会略微增加视觉模型输入长度，无额外调用开销（打标本来就跑）。
