# 人格聊天：接入通义千问角色模型

日期：2026-09-30

## 需求

机器人只会回指令，非指令内容一律无视。希望它有个「人格」：非指令的自然语言也
能聊起来，人格来自《NO GAME NO LIFE》的机凯种**依蜜尔爱因（Emir-Eins）**——
正好和机器人名字、GitHub 仓库名（Emir-Eins）对得上。

素材来自另一个 AI 在 `C:\DSH\persona` 搭的流水线：下 EPUB → 拆 116 章 →
抽出她出场的 17 个文件的段落（`her_scenes.md`）→ 写成角色卡 `依蜜尔爱因.md`。

## 设计

### 触发规则（用户指定）

| 场景 | 是否触发 |
|---|---|
| 单聊非指令文本 | ✅ |
| 群里被 @（非指令文本） | ✅ **无论该群是否开启「全量模式」** |
| 群「全量消息」模式（非 @） | ❌ |
| 任何指令 | ❌ 走指令逻辑 |

**完全被动**：只在收到消息时回复，从不主动推送。按会话限流（默认 5 秒）。

### 全量模式下如何可靠识别「被 @」（抓包解决）

群主开启「接收所有消息」后，**@机器人**和**回复别人**都会走 `GROUP_MESSAGE_CREATE`，
且正文开头都会带 `<@openid>` —— 仅凭正文**无法区分**，这是最初群里不开人格的原因。

抓了一条真实 payload 做字段级 diff 后找到可靠信号：原始 payload 里有 **`mentions`
数组**，被 @ 的实体中机器人自己那条带 `is_you: true`：

```json
"mentions": [{ "is_you": true, "bot": true, "username": "依蜜尔爱因-测试中",
               "member_openid": "FCF6...", "scope": "single", "member_role": "member" }]
```

`@机器人` 与 `回复别人` 的 diff 里，只有 `mentions[0].is_you` 是决定性的。
于是实现 `mentioned_bot()`（读 `raw_events.get_raw()` 的 `mentions[].is_you`），
正文里的 `<@openid>` 只用来剥提及、不参与判断。

**这是本次排查最大的收获**：不必依赖「正文里有没有 @」，`mentions` 是结构化、
不会误判的。

抓包方法（已顺手修好，见"踩过的坑"）：`QQ_BOT_DUMP_EVENTS=1` 重启，原始事件写入
`logs/raw_events.jsonl`；本例中两条消息的 `content`/`id`/`timestamp`/`mentions`/
`message_scene.ext` 有差异，其余字段一致。

### 分层

| 模块 | 职责 |
|---|---|
| `persona.py` | 调模型：历史 + 这句话 → 一句回复。**不存储、不过滤、不发送** |
| `chat_store.py` | 按会话隔离的短期记忆（`data/chat.db`） |
| `sensitive.py` | 敏感词过滤（命中即静默） |
| `bot.py` | 把三者串起来，失败一律静默 |

### 记忆：双重过期

存在 `data/chat.db`（独立于图库的 `images.db`），scope 为
`group:<群openid>` / `c2c:<用户openid>`：

- **条数上限**：每会话最多 `QQ_BOT_CHAT_MEMORY` 条（默认 100）
- **存活时间**：上下文只留 `QQ_BOT_CHAT_MEMORY_MINUTES` 分钟（默认 20），
  过期消息在**读取时被过滤**、在**写入时被物理删除**
- 群与群、群与单聊**互不串台**

**只发图片也算一轮上下文**：私聊发图时机器人不回复，但会写一条
「（发了一张图片）」进上下文，让紧接着的下一句（「这张图好可爱」）能接得上。
占位文本写明"图片"，是为了让模型知道自己看不到图、不要瞎编内容。

### 三道静默

1. 用户这句话命中敏感词 → 不回复，**也不写进上下文**
2. 模型调用失败 / 超时 / 被内容安全拦截 → 不回复
3. **模型回复命中敏感词 → 丢弃这条回复**（宁可装死，也不能把暴论发出去）

### 敏感词表

`data/sensitive_words.txt`（1199 条）由 `deploy/fetch_sensitive_words.sh` 从开源词库
[konsheng/Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon)（MIT）
的**政治 / 反动 / 贪腐 / 暴恐**四类合并生成，走 jsDelivr（GitHub raw 在国内服务器常超时），
带多镜像重试。

**故意不取**民生、色情、非法网址等大类：民生类含大量日常词，会疯狂误杀，而本机器人的
目标只是「不碰键政」。「政府」「中央领导」「主席画像」等日常词通过
`deploy/sensitive_allow.txt` 放行。

## 踩过的坑

1. **`str.translate()` 的映射字典必须用字符序号（int）做键**。一开始用
   `chr()` 生成字符串键，全角转换**静默失效**（不报错），导致「测　　试」这类
   全角绕过拦不住。
2. **注释判断要在 `normalize()` 之前**。`normalize()` 会把 `#` 当分隔符剥掉，
   于是 `line.startswith("#")` 永远不成立，注释行会被当成词收进词表。
3. **配置必须惰性读取**。`bot.py` 里 `load_dotenv()` 在 import 语句**之后**执行，
   `persona.py` 若在 import 期间就把环境变量读成模块常量，读到的会是空值 →
   人格聊天**静默永久关闭**（日志上还看不出来）。改成函数内 `os.getenv` 后正常。
4. **`raw_events.py` 的抓包开关从来就没生效过**（项目里的既有 bug，不是这次引入的）：
   同样是在 import 期读 `QQ_BOT_DUMP_EVENTS`，而那时 `.env` 还没加载。第一次抓包
   扑空就是这个原因。已改成 `dump_enabled()` 惰性判断。
5. jsDelivr 从国内服务器偶发 SSL 握手超时，词表脚本加了 3 镜像 × 2 重试，
   并改成「单个文件失败不致命，但显式告警」——避免"看起来成功、其实漏了一整类词"。
6. **测试污染**：`_test_reply_policy.py` 的单聊用例会走到 `persona_reply`，
   在**服务器上**跑测试（`.env` 里有 Key）时会真的调模型、并往 `data/chat.db` 写。
   已在测试里显式关掉人格并换成临时库。

## 已知限制

- 「键政」≠「敏感词」：词库拦得住显性敏感词，但「这政策不合理」这类用词正常的
  键政讨论拦不住。模型自身的内容安全是第一道防线，词库只是第二道。
- 简繁/拼音变体未做归一化（只做了全角 + 分隔符）。
- ~~全量模式下无法区分「@机器人」与「回复别人」~~ → **已解决**（`mentions[].is_you`）。
- `chat.db` 不进坚果云备份（只是可丢弃的上下文，且协议承诺只留 100 条）。
