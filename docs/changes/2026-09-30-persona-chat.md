# 人格聊天：接入通义千问角色模型

日期：2026-09-30

## 需求

机器人只会回指令，非指令内容一律无视。希望它有个「人格」：非指令的自然语言也
能聊起来，人格来自《NO GAME NO LIFE》的机凯种**依蜜尔爱因（Emir-Eins）**——
正好和机器人名字、GitHub 仓库名（Emir-Eins）对得上。

素材来自另一个 AI 在 `C:\DSH\persona` 搭的流水线：下 EPUB → 拆 116 章 →
抽出她出场的 17 个文件的段落（`her_scenes.md`）→ 写成角色卡 `依蜜尔爱因.md`。

## 设计

### 触发规则（用户指定）

| 场景 | 是否触发 |
|---|---|
| 单聊非指令文本 | ✅ |
| 群里被 @（非指令文本） | ✅ |
| 群「全量消息」模式（非 @） | ❌ 默认不做 |
| 任何指令 | ❌ 走指令逻辑 |

**完全被动**：只在收到消息时回复，从不主动推送。按会话限流（默认 5 秒）。

### 为什么「全量模式」默认不做

群主开启「接收所有消息」后，**@机器人**和**回复别人**都会在正文开头留下
`<@openid>`（见 `raw_events.py` 的说明），仅凭文本**无法可靠区分**。误判的代价是
机器人给「回复别人」的消息插话。所以默认关闭，提供 `QQ_BOT_CHAT_IN_ALL=1` 作为
显式逃生门，并接受该误触发。

> 待办：抓一条真实的「全量模式下 @机器人」payload，看有没有可利用的区分字段。

### 分层

| 模块 | 职责 |
|---|---|
| `persona.py` | 调模型：历史 + 这句话 → 一句回复。**不存储、不过滤、不发送** |
| `chat_store.py` | 按会话隔离的短期记忆（`data/chat.db`） |
| `sensitive.py` | 敏感词过滤（命中即静默） |
| `bot.py` | 把三者串起来，失败一律静默 |

### 三道静默

1. 用户这句话命中敏感词 → 不回复，**也不写进上下文**
2. 模型调用失败 / 超时 / 被内容安全拦截 → 不回复
3. **模型回复命中敏感词 → 丢弃这条回复**（宁可装死，也不能把暴论发出去）

### 敏感词表

`data/sensitive_words.txt`（1199 条）由 `deploy/fetch_sensitive_words.sh` 从开源词库
[konsheng/Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon)（MIT）
的**政治 / 反动 / 贪腐 / 暴恐**四类合并生成，走 jsDelivr（GitHub raw 在国内服务器常超时），
带多镜像重试。

**故意不取**民生、色情、非法网址等大类：民生类含大量日常词，会疯狂误杀，而本机器人的
目标只是「不碰键政」。「政府」「中央领导」「主席画像」等日常词通过
`deploy/sensitive_allow.txt` 放行。

## 踩过的坑

1. **`str.translate()` 的映射字典必须用字符序号（int）做键**。一开始用
   `chr()` 生成字符串键，全角转换**静默失效**（不报错），导致「测　　试」这类
   全角绕过拦不住。
2. **注释判断要在 `normalize()` 之前**。`normalize()` 会把 `#` 当分隔符剥掉，
   于是 `line.startswith("#")` 永远不成立，注释行会被当成词收进词表。
3. **配置必须惰性读取**。`bot.py` 里 `load_dotenv()` 在 import 语句**之后**执行，
   `persona.py` 若在 import 期间就把环境变量读成模块常量，读到的会是空值 →
   人格聊天**静默永久关闭**（日志上还看不出来）。改成函数内 `os.getenv` 后正常。
4. jsDelivr 从国内服务器偶发 SSL 握手超时，词表脚本加了 3 镜像 × 2 重试，
   并改成「单个文件失败不致命，但显式告警」。

## 已知限制

- 「键政」≠「敏感词」：词库拦得住显性敏感词，但「这政策不合理」这类用词正常的
  键政讨论拦不住。模型自身的内容安全是第一道防线，词库只是第二道。
- 简繁/拼音变体未做归一化（只有全角 + 分隔符）。
- 全量模式下无法区分「@机器人」与「回复别人」（见上）。
- `chat.db` 不进坚果云备份（只是可丢弃的上下文，且协议承诺只留 100 条）。
