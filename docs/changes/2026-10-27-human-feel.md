# 活人感：少报告体 + 延迟 + 长回复拆条

- 日期：2026-10-27
- 方向：**机娘味保留，少报告体**（用户选定）
- 涉及：`persona/依蜜尔爱因.md`、`bot.py`、`_test_chat_style.py`（新）、
  测试隔离（`_test_persona` / `_test_commands` / `_test_reply_policy` /
  `_test_group_context`）、`.env.example`、`README.md`

## 需求

现在的回复“太像状态机”：每句挂【标签】、一次一大段、秒回。目标是像大肥鱼那样
有活人感，但保留依蜜尔爱因的机娘口癖，不改成普通群友。

## 角色卡改了什么

- **标签从“每句格式”降级为“口癖”**：报告/演算/慌乱/毒舌/情绪强时才用；
  日常闲聊可以完全不用。群聊一条回复最多一个标签，禁止每句都挂。
- **群聊 1~2 句封顶，尽量 60 字内**；先接话再给信息，不写报告体。
- **允许短反应**：`？`、`草`、`行吧`、`啊这`、`……` 都是完整回复。
- **群聊上下文要会用**：顺着刚聊到的内容接，不复述背景、不硬编占位图。
- **偶尔不完美**：可以停顿、改口、说一半；但不故意错字连篇。
- 更新对话示例：原来「今天好累」是【报告】+【提议】+【建议】三段，
  现在改成一句「又熬夜了？……过来，本机借你靠一会儿」；
  看图示例也从「检测到发色/瞳色」改成先回应画面。

## 代码改了什么

### 1. 回复延迟

- `QQ_BOT_CHAT_DELAY_MIN` / `QQ_BOT_CHAT_DELAY_MAX`（默认 0.5 / 1.8 秒）；
- 回复超过 100 字再额外加 0.2~0.8 秒；
- `0` / `0` 关闭。只作用于人格回复，指令/公告/图片链路不受影响。

### 2. 长回复拆条

- `QQ_BOT_CHAT_SPLIT=1` 开启（默认关，线上已开）；
- 超过 `QQ_BOT_CHAT_SPLIT_CHARS`（默认 80 字）才拆，最多
  `QQ_BOT_CHAT_SPLIT_MAX` 条（默认 2，范围 2~4）；
- 优先在句末标点断开，其次逗号/顿号/空格，最后硬切；
- **代码块和 URL 不拆**，避免把可复制内容切断；
- 每条用 `next_msg_seq(message.id)` 递增 `msg_seq`，否则第二条会被
  QQ 以 `40054005` 去重拒掉；条间停 0.35~0.9 秒。

## 测试

新增 `_test_chat_style.py`：

- 短回复不拆、URL/代码块不拆；
- 长回复拆 2 段、不丢字、在标点后断开、不超过 max_parts；
- `persona_reply` 实际发 2 条，内容拼起来等于原回复；
- `msg_seq` 从 1 递增到 2。

其他会调用 `persona_reply` 的测试显式把延迟设为 0、拆条关掉，避免变慢/断言失败。

## 配置（线上）

```ini
QQ_BOT_CHAT_DELAY_MIN=0.5
QQ_BOT_CHAT_DELAY_MAX=1.8
QQ_BOT_CHAT_SPLIT=1
QQ_BOT_CHAT_SPLIT_CHARS=80
QQ_BOT_CHAT_SPLIT_MAX=2
```

## 回滚

- 关延迟：`QQ_BOT_CHAT_DELAY_MIN=0`、`QQ_BOT_CHAT_DELAY_MAX=0`；
- 关拆条：`QQ_BOT_CHAT_SPLIT=0`；
- 角色卡回滚：`/root/依蜜尔爱因.md.bak-*`（部署脚本会备份）。

## 备注

- 官方 Bot 没有“正在输入”状态，只能用延迟模拟“看完再打字”；
- 拆条不是越多越好，2 条是默认上限；群聊里 3 条以上容易像刷屏；
- 下一步可做“全量模式低概率接话”（被动回复，不占主动额度），但需要群级冷却和开关。
